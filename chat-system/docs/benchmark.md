# 채팅 시스템 벤치마크 결과

메시지 전달 지연과 처리량을 실측한 결과다. 재현은 `./gradlew benchmarkTest`(결과가 `build/reports/benchmark.md`로도 출력된다).

## 실행 환경

| 항목 | 값 |
| --- | --- |
| 머신 | Apple M1 Pro (10 core) / 32GB |
| OS | macOS 26.5.1 |
| JDK | OpenJDK 21 |
| 인스턴스 | 3대 (단일 JVM 내 별도 Spring 컨텍스트, server-1/2/3) |
| Redis | redis:7-alpine (로컬) |
| 측정 대상 | 인스턴스 간 지향 전달 및 그룹 팬아웃 (Redis Pub/Sub 경유) |

값은 이 머신 기준 참고치다. 인스턴스·클라이언트·Redis 가 한 머신을 공유하므로 절대 수치보다 경향으로 본다.

## 측정 방법

- 발신 시각(밀리초)을 메시지 본문에 실어 보내고, 수신 시점과의 차이로 지연을 계산한다. 발신자와 수신자가 같은 JVM 이라 clock 이 공유돼 시각차가 유효하다.
- 지연과 처리량을 분리해 측정한다.
  - 지연: 순차 1건씩 보내고 그 메시지가 도착한 뒤 다음을 보낸다. 큐 대기(포화)가 없어 실제 전달 지연을 잰다. 표본 500건(warmup 50 제외).
  - 처리량: 연속 발행(burst)으로 초당 전달량을 잰다. 직접 5000건, 팬아웃 100건 × 150명 = 15000 전달.
- 초기에 3000건을 burst 로 보내 지연을 재니 P50 이 3초로 나왔는데, 이는 전달 지연이 아니라 발신 큐 대기였다. 그래서 위와 같이 분리했다.

## 결과 (3회 실측)

### 전달 지연 — 크로스 인스턴스 1:1 (인스턴스1 → 인스턴스3, 무포화)

| 실측 | 표본 | P50 | P95 | P99 | Max |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1회 | 500 | 2ms | 4ms | 7ms | 12ms |
| 2회 | 500 | 3ms | 7ms | 10ms | 13ms |
| 3회 | 500 | 3ms | 6ms | 9ms | 42ms |
| 대표값 | — | ~3ms | ~6ms | ~9ms | 12~42ms |

### 처리량 — 연속 발행 (burst)

| 시나리오 | 전달 건수 | 1회 | 2회 | 3회 | 대표값 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 직접 1:1 | 5000 | 711 msg/s | 466 msg/s | 601 msg/s | ~600 msg/s (466~711) |
| 그룹 팬아웃 150명(3인스턴스 분산) | 15000 | 1272 /s | 1283 /s | 1309 /s | ~1290 deliveries/s |

## 해석

- 크로스 인스턴스 전달 지연은 무포화 상태에서 P95 약 6ms다. WebSocket 프레임 수신 → 세션 레지스트리 조회(Redis GET) → Pub/Sub 발행 → 대상 인스턴스 구독·전달까지 포함한 값이다. 로컬 환경에서 실시간 채팅에 충분한 수준이다.
- Max 지연이 회차별로 12~42ms 로 튄다. 단일 JVM 에서 3개 인스턴스와 클라이언트가 CPU·GC 를 공유해 생기는 지터로 본다.
- 직접 처리량은 466~711 msg/s 로 편차가 크다. 발신·수신·라우팅·Redis 왕복이 한 머신에서 경쟁하기 때문이다. 팬아웃 처리량(약 1290 deliveries/s)은 회차 간 안정적이다.
- 팬아웃은 메시지 1건이 150 전달로 증폭되지만, 서버 단위 팬아웃(서버당 1회 전파 후 로컬 분배)이라 Redis 발행량은 메시지 수에 비례하고 전달 수에 비례하지 않는다.

## 한계

- 단일 호스트 측정이다. 물리적으로 분산된 다중 호스트(별도 서버·K8s)의 네트워크 지연은 반영되지 않는다.
- 단일 JVM 3 인스턴스라 프로세스 격리·자원 경쟁 특성이 실제 배포와 다르다. 분리 프로세스 기능 검증은 `./gradlew composeTest`(docker-compose)로 별도 수행한다.
- 전문 부하 도구(k6·Gatling)가 아닌 JVM 내 측정이라, 수만 소켓·장시간 지속 부하·꼬리 지연 정밀 측정에는 적합하지 않다.
